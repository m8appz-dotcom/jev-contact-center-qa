# Fase 4 — Auditoría por lotes (CLI)
- Qué cambió: `jevqa/pipeline.py` (`leer_entrada`, `auditar`, `RateLimiter`, `EntradaInvalidaError`, `SalidaInvalidaError`), `jevqa/__main__.py` (`python -m jevqa auditar <entrada> [--salida] [--fake]`; salida por defecto `<entrada>.auditado.csv`; exit 0 ok, 2 entrada inválida, 3 autenticación, 4 filas en error, 5 salida con otra cabecera), `tests/test_pipeline.py` (19 tests), `tests/fixtures/mini.csv` (5 filas).
- Diseño: anonimiza (agente + columna opcional `cliente`) antes de `build_request`; tokens estimados ceil(len(JSON)/3) > 32.000 → `demasiado_larga` sin llamada; 8 hilos con limitador ≤ 1.000 llamadas/min (reloj inyectable); reanudable: conserva `ok`/`demasiado_larga`, reintenta `error`, escribe cada fila con flush; `JevAuthError` aborta conservando lo escrito. La salida no lleva texto ni datos personales.
- Revisión (corregido en la fase): fichero inexistente / no UTF-8 / CSV mal formado y filas con campos de menos o de más daban traceback (o tumbaban el lote) → `EntradaInvalidaError` con número de fila; al relanzar con otra entrada se borraban resultados ya pagados de otros ids → ahora se conservan.
- Comando: `python -m unittest tests.test_pipeline -v` → 19 tests, 0 fallos; `python -m jevqa auditar tests/fixtures/mini.csv --fake` → exit 0 (relanzado: 5 saltadas, 0 llamadas); suite completa 121 tests, 0 fallos.
- Riesgo: si `JevAuthError` llega con llamadas en vuelo, sus resultados se pierden (sin coste en la práctica: con credenciales malas no se factura). La salida CSV va en UTF-8 sin BOM (Excel puede mostrar mal las tildes; se decide en la fase 6). El CLI de verificación deja `tests/fixtures/mini.auditado.csv` si no se pasa `--salida` (no versionado; se borró tras verificar).
